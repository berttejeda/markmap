# Checkbox Persistence Feature

The checkbox persistence feature automatically replaces SVG checkboxes in your markmap with interactive HTML input checkboxes that persist their state across page reloads using localStorage.

## Features

- ✅ Automatic checkbox replacement
- ✅ Persistent state across page reloads
- ✅ Unique identification based on content
- ✅ Automatic observation of dynamically added checkboxes
- ✅ Simple API for managing states

## Usage

### Basic Setup

Enable checkbox persistence when creating your markmap:

```typescript
import { Markmap } from 'markmap-view';

const mm = Markmap.create(svg, {
  checkboxPersistence: true
});
```

Or enable it after creation:

```typescript
const mm = new Markmap(svg);
mm.setOptions({ checkboxPersistence: true });
```

### Public API Methods

#### Get Checkbox States

Retrieve all saved checkbox states:

```typescript
const states = mm.getCheckboxStates();
console.log(states); // { 'checkbox-12345': true, 'checkbox-67890': false, ... }
```

#### Clear Checkbox States

Clear all saved checkbox states from localStorage:

```typescript
mm.clearCheckboxStates();
```

#### Manually Process Checkboxes

Manually trigger checkbox processing (normally done automatically):

```typescript
const count = mm.processCheckboxes();
console.log(`Processed ${count} checkboxes`);
```

### Advanced Usage

You can also use the checkbox persistence utilities directly:

```typescript
import {
  CheckboxPersistenceManager,
  loadCheckboxStates,
  saveCheckboxStates,
  clearCheckboxStates,
  processCheckboxes,
  getCheckboxId,
} from 'markmap-view';

// Create a manager for a specific container
const manager = new CheckboxPersistenceManager(document.body);
manager.init();

// Load states
const states = loadCheckboxStates();

// Save states
saveCheckboxStates({ 'checkbox-123': true });

// Clear all states
clearCheckboxStates();

// Process checkboxes in a container
const count = processCheckboxes(document.body);

// Get a unique ID for checkbox content
const id = getCheckboxId('My checkbox text');

// Clean up when done
manager.destroy();
```

## How It Works

1. **Detection**: The system looks for SVG checkboxes with specific attributes:
   - `width="16"`
   - `height="16"`
   - `viewBox="0 -3 24 24"`

2. **Identification**: Each checkbox is assigned a unique ID based on a hash of its associated text content.

3. **Replacement**: SVG checkboxes are replaced with HTML `<input type="checkbox">` elements.

4. **State Management**: 
   - Checkbox states are stored in localStorage under the key `markmap-checkbox-states`
   - States are loaded on initialization and applied to checkboxes
   - State changes are automatically saved

5. **Dynamic Observation**: A MutationObserver watches for new checkboxes added to the DOM and processes them automatically.

## Configuration Options

The checkbox persistence feature is controlled by a single boolean option:

```typescript
interface IMarkmapOptions {
  // ... other options
  checkboxPersistence: boolean; // Default: false
}
```

## Storage Format

Checkbox states are stored in localStorage as JSON:

```json
{
  "checkbox-12345": true,
  "checkbox-67890": false,
  "checkbox-54321": true
}
```

The keys are generated by hashing the text content associated with each checkbox, ensuring consistent identification across page reloads.

## Browser Compatibility

The checkbox persistence feature requires:
- localStorage support (available in all modern browsers)
- MutationObserver API (available in all modern browsers)

## Performance Considerations

- The feature uses a debounced retry mechanism (up to 20 attempts, 250ms apart) to ensure checkboxes are available before processing
- MutationObserver efficiently watches for new checkboxes without polling
- State updates are synchronous and lightweight

## Example

Here's a complete example:

```typescript
import { Markmap } from 'markmap-view';

// Create markmap with checkbox persistence enabled
const svg = document.querySelector('#markmap');
const mm = Markmap.create(svg, {
  checkboxPersistence: true
});

// Set your data
await mm.setData(markmapData);

// Later, you can check what states are saved
console.log('Current checkbox states:', mm.getCheckboxStates());

// Clear all states if needed
mm.clearCheckboxStates();

// Clean up when done
mm.destroy();
```

```typescript
interface CheckboxStates {
  [key: string]: boolean;
}

class CheckboxPersistenceManager {
  constructor(container?: Element);
  init(): void;
  destroy(): void;
  getStates(): CheckboxStates;
  clearStates(): void;
  process(): number;

// Utility functions
function getCheckboxId(textContent: string): string;

function saveCheckboxStates(states: CheckboxStates): void;
function replaceSVGWithCheckbox(svg: SVGElement): HTMLInputElement | null;
function processCheckboxes(container?: Element): number;

```

## Migration from Script Version

If you were using the standalone script version (as in the original `generate-markmap.sh`), migrating to the built-in feature is simple:

**Before (script injection):**
```html
<script>
  // 150+ lines of checkbox persistence code
</script>
```

**After (built-in):**
```typescript
Markmap.create(svg, { checkboxPersistence: true });
```

The functionality is identical, but now it's built into the library with a cleaner API.
